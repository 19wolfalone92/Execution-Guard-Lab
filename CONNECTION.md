# Форма ChatGPT — данные пока не готовы для создания подключения

- Название: **Execution Guard Lab**
- Описание: **Independent computation, diagnostics, evidence verification and quality assurance tools.**
- Подключение: URL-адрес сервера (целевой вариант).
- Фактический URL: **НЕ ПОЛУЧЕН. Нечего вводить в поле URL сейчас.** Не использовать loopback, временный sandbox, URL основного Pro или предполагаемый workers.dev.
- Аутентификация: OAuth (целевая; resource server локально проверен с синтетическими JWT, внешний issuer не подключён).
- Расширенные OAuth: фактический issuer/client_id, регистрация и redirect URI не подтверждены. Не заполнять вымышленными значениями.
- 23/23 инструмента обнаружены локально по TLS, 0/23 удалённо, 0/23 в ChatGPT.

После реальной удалённой квалификации: ChatGPT web → Plugins → «+» → Add custom MCP server → URL-адрес сервера → точный проверенный HTTPS URL /mcp → OAuth → параметры отдельного OAuth-клиента → ознакомиться с рисками → создать/установить плагин. Использовать фактический redirect URI из management page. При RFC 9207 поддержке стабильный redirect URI может быть `https://chatgpt.com/connector_platform_oauth_redirect`; в другом режиме используется URI с callback ID. Не переносить callback/client ID из Pro. При статическом OAuth client secret вводить только в официальной форме, не в чате. Динамическая регистрация/CIMD требуют поддержки issuer и подтверждения; ничего из этого не выполнено.

В новом обычном чате выбрать именно @Execution Guard Lab. Сравнить список с `MCP_SCHEMAS.json`, для каждого инструмента использовать синтетические эталоны из `BASELINE_RERUN_RPC.json`, сверить structuredContent и фактические tool call payload. Повторить все 23 в другой сессии. Не считать ручное вычисление, SDK или подставленный ответ вызовом ChatGPT. При отсутствии инструмента записать точный факт, не приписывать без доказательства блокировке OpenAI. При явном отказе безопасности остановить операцию.
