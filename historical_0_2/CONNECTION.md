## Выводы

Help Center явно описывает Business, Enterprise/Edu для полного MCP и Pro для read/fetch. Поддержка добавления нового собственного сервера на Plus в обычном чате в этом источнике не подтверждена; это не доказывает отсутствие индивидуальной доступности. Наличие существующего Pro-плагина также не подтверждает право регистрации новой лаборатории. Документация указывает web-интерфейс, а не мобильную регистрацию. В документах, изученных при этом этапе, не найден универсальный лимит 6 или 26 инструментов; это не доказательство отсутствия всех внутренних лимитов. Обновление инструментов требует Refresh и новой сессии, в workspace может требовать review/публикации администратором. OAuth, CIMD/DCR/PKCE, securitySchemes и подтверждения зависят от типа подключения и сервера; аннотации не заменяют проверки разрешений. Пакет с манифестом не равен работающему MCP endpoint.

## Фактическое препятствие

Доступные в этой сессии операции не содержат регистрации новой MCP connection или деплоя отдельного Lab endpoint. Нет работающего постоянного HTTPS endpoint или разрешенного настроенного Secure MCP Tunnel. Не было отказа регистрации Lab от OpenAI: регистрацию не выполняли, поскольку отсутствуют предпосылки. Не создан пустой plugin wrapper. Не изменены permissions. Не предпринимать альтернативные попытки выполнить ранее явно запрещенную операцию GitHub.

## Минимальный следующий шаг владельца

1. В браузере открыть ChatGPT Plugins → `+` → `Add custom MCP server` и проверить, доступен ли пункт в своем аккаунте. Если отсутствует/запрещен, не обходить ограничение; запросить подтверждение допустимой регистрации в поддержке.
2. Для разрешенного тестирования новой лаборатории потребуется независимо размещенный квалифицированный MCP endpoint HTTPS или штатный Secure MCP Tunnel (см. официальное руководство, только при наличии права на его использование). Локальный `http_lab.py` не предназначен для выставления в интернет. Перед публичным размещением требуется полноценный защищенный transport, квоты/ограничения, мониторинг и при необходимости OAuth. Не использовать Production Pro и его OAuth/DB/токены. Не отправлять секреты в чат.
3. Если аккаунт разрешает добавление и лабораторный endpoint готов, ввести имя `Execution Guard Lab`, выбрать endpoint `/mcp` или разрешенный Tunnel, настроить фактическую аутентификацию (noauth только для согласованного изолированного теста на синтетических данных), изучить предупреждение и подтвердить. Выбрать `Create as a plugin`, проверить обнаруженные схемы. Сохранить число и имена инструментов.
4. Установить плагин, открыть обычный новый чат (не Work), выбрать `@Execution Guard Lab`. Запросить `text_sha256` для `abc`, `math_calculate` для 12/4, затем остальные фикстуры из `MCP_EVIDENCE.json`. Сверять именно фактические вызовы, ответы, а не текстовые заявления модели. Проверить ошибки, повторные вызовы, новую сессию и Refresh после легитимного обновления сервера. Зафиксировать имя инструмента, аргументы без секретов, точную ошибку, request ID, если доступен.
5. L4 — обнаружение конкретного инструмента в обычном ChatGPT; L5 — фактический вызов с правильным ответом; L6 — повторные сессии/стабильность. При явном запрете остановиться, зафиксировать и дождаться официального разрешения, не пробовать обход.

## Разрешения

Лабораторные инструменты не требуют GitHub, Binance, Cloudflare D1/KV или учетных данных проектов. Дополнительные права нужны не для арифметики/анализа, а для законного подключения и размещения, если они доступны. Для будущих функций с данными проектов нужны отдельные разрешенные read-only источники и квалификация. Никаких реальных торговых или изменяющих операций.
