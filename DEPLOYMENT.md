# Развёртывание: отдельный кандидат, не опубликованный сервис

## Выбор архитектуры

A Cloudflare Python Workers: сохраняют Python, но работают через Pyodide/V8, имеют ограничения пакетов и CPU. Не установлены pywrangler/Wrangler, нет доступной авторизованной операции Cloudflare deployment и отдельной конфигурации Lab. Ни AST/ZIP в Pyodide, ни перенос OAuth не испытаны. Отклонено на этом этапе.

B TypeScript Cloudflare Workers: потребовал бы переноса всех 23 функций, точного эквивалента Python AST и ZIP, сравнения результатов, отдельной OAuth инфраструктуры. Не проверен; перенос не начат, чтобы не ухудшать функциональность.

C CPython ASGI + TLS: выбран для кандидата, поскольку существующее ядро 23 функций реально прошло TLS и регрессии. Docker/Compose — конфигурация для изолированного хоста; не построена и не развёрнута. TLS напрямую в Uvicorn, без доверия proxy headers. Публичный DNS/TLS и стабильность хоста не проверены. Стоимость зависит от уже имеющегося у владельца хоста; платных ресурсов не создавалось.

D OpenAI Secure MCP Tunnel: официальный разрешённый механизм для приватных серверов. Требует уже работающего хоста, `tunnel-client`, Platform tunnel identity и разрешений Tunnels Read/Manage/Use. В окружении клиента/идентификатора нет. Выбирается в ChatGPT как Tunnel, а не как URL. Не заменяет OAuth и не является обходом ограничений. Возможен после отдельной квалификации, если владелец выберет этот режим.

## Единственный следующий шаг владельца

Предоставить или выбрать отдельный постоянно доступный авторизованный Linux-хост для Lab (может быть существующее устройство/сервер), с возможностью установки официальных пакетов и проверки зависимостей. Не передавать в чат пароли, API-токены, SSH private keys или OAuth client secret. Не использовать ресурсы основного Pro. Пока хост и отдельно управляемый OAuth issuer не определены, публичный endpoint не создавать.

## Staging — только после появления такого хоста

1. Распаковать комплект, проверить `sha256sum -c MANIFEST.sha256` и исходный ZIP 0.2.0. Установить целевые зависимости в отдельной venv: `python -m pip install -r requirements-test.txt -r requirements-sdk.txt`.
2. Выполнить `python production_preflight.py`, `python -m pip check`, `python -m pytest -q`, `python sdk_probe.py --check-install`. Провести свежий аудит фактически установленного полного дерева (например, `pip-audit` из официального индекса), отдельно проверить системный OpenSSL и образ. Не продолжать при неисправленных advisory или несовпадении версий. В этой среде исправленные версии не установлены; их совместимость не подтверждена.
3. Настроить отдельный, доверенный OAuth authorization server; не использовать существующие Pro OAuth секреты. Внешний issuer должен поддерживать HTTPS metadata, authorization-code + PKCE S256, нужный client_id/redirect URI, обновление токенов, выдачу JWT access token по RFC 9068 (`typ=at+jwt`, RS256, `kid`, точный `iss`, `sub`, `client_id`, `aud` = полный MCP resource, scope ровно `lab:read`, целые `iat`/`exp`, TTL ≤900 секунд). Нужен один отдельный owner subject. Никаких ID token вместо access token. Если issuer не выдаёт такой профиль, остановить интеграцию и корректно адаптировать/квалифицировать сервер, не ослаблять проверку.
4. Выбрать собственный DNS hostname и получить действующий TLS сертификат на него. `LAB_RESOURCE` должен быть каноническим HTTPS URL с путём `/mcp`; `LAB_ISSUER` точным issuer из metadata. `LAB_OWNER_SUB`, `LAB_CLIENT_ID`, `LAB_KEY_ID` взять из отдельной OAuth конфигурации. Скопировать `lab.env.example` в `lab.env` и заполнить **локально**. В `lab-keys/` разместить публичный verification PEM, TLS fullchain и private key; ограничить доступ к закрытому ключу, предоставить read для UID 10001, не помещать в исходники или ZIP. OAuth secret, refresh/access tokens в env или архив не включать. Публичный ключ фиксируется; при ротации ключа контролируемо заменить PEM/kid и перезапустить.
5. Сначала использовать `docker compose build` и `docker compose up -d` на изолированном хосте. Сервис по умолчанию доступен лишь на loopback:8443; публичный адрес не создаётся. Чтобы провести локальный TLS probe с выбранным именем, разрешить DNS/hosts на тестовый адрес на авторизованной машине и сохранить правильный Host/issuer/audience, либо настроить staging на отдельном каноническом hostname:8443. Не использовать `-k`, не отключать TLS verify. Не запускать тестовый launcher на сети.
6. После успешного patched runtime, security audit и локального SDK-run: провести контролируемую удалённую staging-проверку через собственный DNS и TLS. Для прямого HTTPS, только при наличии свободного порта 443 и разрешения администратора, отдельно изменить mapping Compose с `127.0.0.1:8443:8443` на `443:8443`, настроить firewall/ограничение трафика. Не открывать до проверки. Предпочтителен доступ из разрешённой сети на этапе испытаний. Убедиться, что сертификат валидный и совпадает hostname, `/health`/`/version` возвращают 0.3.0, metadata доступна, `/mcp` без токена 401.
7. В авторизованной среде получить отдельный короткоживущий access token через issuer; `python sdk_probe.py --url "$LAB_RESOURCE" --output SDK_EVIDENCE.json` запросит его скрытым вводом. Не передавать через аргументы shell, чат, историю или логи. SDK fixture должен использовать выделенный разрешённый клиент, тот же exact client_id, который настроен для проверяемого экземпляра. Уточнить реальные параметры и провести issuer E2E: auth code, PKCE, refresh, expiry, fake token, wrong owner, callback. Этот скрипт не выполняет интерактивный OAuth browser flow и не является его доказательством. Проверить 23 инструмента повторно после restart/redeploy, реальные resource limits, TLS публичным trust store, защиту и health. Записать deployment ID, source/image digest, время, публичный URL и результаты. Только после этого переходить к регистрации ChatGPT.

## Пределы конфигурации

Dockerfile использует Python 3.13-slim tag; image digest и скачиваемые wheels пока не зафиксированы/проверены, сборку не объявлять воспроизводимой. Compose задаёт 1 CPU, 256 MiB, 64 PID, readonly root, non-root, no-new-privileges, drop ALL, read-only key mount. Это заявленная конфигурация, не доказательство применения cgroup. Rate limit глобальный на один процесс; злоупотребление может исчерпать общий бюджет, требуется отдельная edge-защита на публичной инфраструктуре. Нет per-tool hard CPU kill и автоматической ротации ключей; сетевой TLS handshake/slow headers должны дополнительно ограничиваться инфраструктурой. Не публиковать без внешней квалификации.

## Восстановление

Контрольная точка `execution-guard-lab-0-3-0`, ревизия 1 сохранена/прочитана. Исходная `execution-guard-lab-0-2-0` ревизия 1 неизменна. Главный `execution-guard-0-6-0` ревизия 43 не перезаписывать. При сбое staging остановить только Lab, сохранить логи без секретов, проверить хеши, повторно собрать после устранения причины. Лаборатория не имеет постоянного состояния; для отката использовать проверенные архивы, не развёртывать старый неаутентифицированный HTTP server публично. При явном security denial остановить соответствующее действие и обратиться к официальному разрешению; не менять способ для обхода.
