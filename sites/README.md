# Execution Guard Lab 1.0.3 для ChatGPT Sites

Приватный Site передаёт MCP-запросы в WebAssembly-реактор CPython. В реактор включены оригинальные `lab.py`, `extensions.py` и `optimized.py`. Их побайтовое совпадение проверяет `scripts/verify-source.py`. Сборка использует версии и SHA-256 из `runtime/deps.json`.

Site предоставляет 23 функции из `worker/catalog.json` и три исходные диагностики `lab_health`, `lab_sha256`, `lab_numeric_verify`. В ответ вычислительной функции добавлен `request_id`. Целочисленный `math_calculate` возвращает также `exact_integer`, если результат выходит за безопасный диапазон JavaScript. Для таких значений используйте строку `exact_integer` при последующих точных расчётах.

## Повторить сборку и испытания

Сборка предназначена для Linux x86-64 с CPython 3.13 и Node.js 24.

```sh
python3.13 -B scripts/prepare.py
npm ci --ignore-scripts
npm run build
npm test
npm run qualify
```

Из клона GitHub выполните также `python3 -B scripts/verify-source.py` с пакетом `jsonschema` из `requirements.lock`. Прогон `npm run qualify` использует исходные сценарии из корня репозитория и тот же пакет для сравнения. Данные прогона сохраняются в `.evidence`. Сборка из зеркала Site использует уже синхронизированные исходники под `runtime` и `worker`.

## Права и восстановление

Доступ в Sites задаётся списком из одной учётной записи владельца. Код обрабатывает вычисления с установленным платформой идентификатором. D1 хранит случайные идентификаторы допусков, состояние и время, а входные данные и идентификатор владельца остаются вне базы. Привязка `DB` нужна для общего лимита 160 допусков на 60 секунд и четырёх активных вычислений. Миграции находятся в `drizzle`.

Бронь до запуска действует 30 секунд. Активация транзакционно проверяет бронь и общий лимит, затем привязывает случайный токен к одному исполнителю. Освобождение требует тот же токен. При неопределённом ответе D1 переход повторяется один раз с теми же идентификаторами. При повторном сбое функция прекращает обработку. Просроченная бронь автоматически перестаёт занимать место. После активации истечение времени само по себе не доказывает остановку вычисления, поэтому активный допуск не перевыдаётся. Старые завершённые записи удаляются при новом допуске. Если активация завершилась неопределённым ответом 503, вызывающая операция заведомо не приступает к вычислению. Она может условно отменить только собственную незапущенную бронь или собственный токен активации. Чужой RUNNING не освобождается, запоздавшая активация блокируется, а при недоступности D1 сохраняется fail-closed. Это не обеспечивает автоматического освобождения RUNNING после жёсткой остановки процесса.

Для отката через историю того же Site выберите сохранённую версию 4 и приватную публикацию. После завершения проверьте список доступа и `lab_health` с версией `1.0.1`. Оба выпуска используют тот же счётчик запущенных операций. Сохранённая версия 1 доступна отдельно для восстановления диагностик `0.9.2`. Наблюдаемые идентификаторы публикации считайте из ответа Sites.

## Pro и Lab

Сначала получите актуальную ревизию проекта и ссылки на исходные данные через Pro. Для расчёта или проверки контрольной суммы передайте Lab минимальный набор входных данных. Сравните результат с независимым эталоном и сохраните его `request_id`, версию Lab и ссылку на доказательство в Pro с ожидаемой ревизией. Перечитайте контрольную точку и проверьте совпадение. Полномочия на изменение внешней системы принадлежат инструменту, который вызван в чате, и правилам этой системы.
